# Feature specification: `m365-powershell` pack

**Feature:** `003-m365-powershell-pack`
**Roadmap:** Phase 3 · Issue #48
**Status:** ready for build approval
**Depends on:** `001-pack-mechanism`. Before building, re-read this spec against the code as built in 001 and report any mismatch instead of improvising.

## Summary

PowerShell repositories get no discovered checks today, because check discovery only reads `package.json`. This feature delivers a bundled `m365-powershell` pack: a PowerShell check proposal adapter, script-standard rules enforced as PSScriptAnalyzer custom rules, a static Microsoft Graph least-privilege check, skills for Microsoft 365 administration automation, and a Microsoft Learn MCP recommendation. Public defaults are generic; the maintainer's personal values live in a private overlay pack.

## User stories

### US1 — PowerShell checks are proposed automatically (P1)

Given a repository with PowerShell scripts, modules, Pester tests or a PSScriptAnalyzer settings file, preparation proposes Pester and PSScriptAnalyzer checks without running them.

### US2 — Script standards are enforced as checks (P1)

Given scripts that break the configured standard, `verify --execute` fails with one precise finding per violation (file, line, rule, message). A clean script passes.

### US3 — Graph permissions are least privilege (P1)

Given a script and its declared Graph application permissions, the check fails when the script uses a Graph command needing a permission it does not declare, and reports declared permissions it never uses.

### US4 — Personal standards without forking the pack (P2)

Given a private overlay pack that sets configuration values (for example `.SYNOPSIS` language `nb` and log path pattern `C:\MK-LogFiles\<ScriptName>.log`), the same rules enforce those values without changing the public pack.

## Functional requirements

- **FR-001 Detection.** The pack's `appliesTo` matches `**/*.ps1`, `**/*.psm1`, `**/*.psd1`.
- **FR-002 Check proposals.** The pack contributes proposals that run through one bundled runner script, `pwsh -NoProfile -NonInteractive -File <pack>/checks/Invoke-PackCheck.ps1 -Check <name>`, for `pester` (when `*.Tests.ps1` files exist), `analyzer` and `graph-permissions`. The runner exits 0 on pass and 1 on findings, writes findings as JSON lines to standard output, and never connects to a tenant or the network.
- **FR-003 Prerequisites.** Missing `Pester` (v5 or later) or `PSScriptAnalyzer` modules are reported by the runner with the install command; they are never installed automatically.
- **FR-004 Script-standard rules** as PSScriptAnalyzer custom rules, each configurable on/off and by value through pack configuration:
  - comment-based help with `.SYNOPSIS` and `.DESCRIPTION` (optional language check for `.SYNOPSIS` by configured language);
  - use of a configured logging function name and, optionally, a log path pattern;
  - main body inside `try`/`catch` with explicit `exit 0` and `exit 1` in scripts (not modules);
  - no aliases (built-in `PSAvoidUsingCmdletAliases`, enabled by the pack settings);
  - no non-ASCII characters in identifiers or literal paths;
  - `SupportsShouldProcess` on functions and scripts whose names use state-changing verbs (`Set`, `New`, `Remove`, `Add`, `Update`, `Disable`, `Enable`, `Invoke`, `Start`, `Stop`, `Reset`, `Grant`, `Revoke`);
  - no hardcoded GUID-shaped tenant or client IDs in assignments, no client secrets, certificate thumbprints or bearer tokens in literals.
- **FR-005 Configuration.** Values come from pack configuration with this precedence: project `.project-init/packs.config.json` → overlay pack → public pack defaults. Public defaults: language check off, logging function name `Write-Log`, log path pattern off.
- **FR-006 Graph permission manifest.** A script declares permissions in a sidecar `<Script>.permissions.json` (`schemaVersion: 1`, `application: [..]`, `delegated: [..]`). Missing manifest for a script that calls Graph is a finding.
- **FR-007 Graph mapping table.** The pack ships a versioned mapping from Microsoft Graph PowerShell cmdlets and Graph REST paths to their least-privileged permissions. It is generated by a maintainer-run script using `Find-MgGraphCommand` from the Microsoft Graph PowerShell SDK, records the SDK version and generation date, and is committed; it is never generated at check time.
- **FR-008 Graph check.** Static analysis of `Invoke-MgGraphRequest`/`Invoke-RestMethod` URIs and `Mg*` cmdlets: under-declared permission → failure; declared but unused → warning; dynamic or unparseable URIs → `unverifiable` finding, never a pass for that call.
- **FR-009 Skills.** App-only Graph authentication (certificate-based), Intune remediation script pairs, Defender/ASR rollout in audit-then-block stages, Conditional Access changes in report-only first, Power Automate flows calling Graph. Each skill states least privilege, logging, idempotency and rollback.
- **FR-010 MCP.** The pack recommends the Microsoft Learn MCP server; it is not installed automatically.
- **FR-011 Private overlay.** Documentation and an example show how to create a private overlay pack containing only configuration values and extra rules, added with `pack add` from a private Git ref.
- **FR-012 No tenant data.** No fixture, example or test contains a real tenant ID, user, group, policy or secret.

## Out of scope

- Connecting to a tenant, running scripts against Graph, or validating that permissions are granted.
- Tenant configuration as code (spec 014).

## Success criteria

- **SC-001** A fixture with one deliberate violation per rule fails each with a precise finding; a clean fixture passes.
- **SC-002** The Graph check passes a correctly declared script, fails an under-declared one, warns on an over-declared one, and reports a dynamic URI as unverifiable.
- **SC-003** Overlay configuration changes rule behavior without editing the public pack.
- **SC-004** Windows CI runs the PowerShell checks; Linux and macOS run them where `pwsh` is available and report clearly when it is not.
